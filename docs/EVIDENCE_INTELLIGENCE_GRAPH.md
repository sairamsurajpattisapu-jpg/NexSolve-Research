# NexSolve Evidence Intelligence Graph Engine

## 1. Executive Summary & Design Rationale
The **Evidence Intelligence Graph** (`nexsolve_core.graph`) establishes a deterministic, cross-modal property graph that connects raw passive network entities (IPs, ports, flows, TCP sessions, communication pairs, 60s temporal windows) with multi-modal behavioral signals (Zeek-inspired session states, RITA-inspired periodicity, NFStream-inspired flow dynamics, Suricata EVE signatures, ML anomaly detections) and recursive world-model forecasts.

Prior to this engine, NexSolve produced disconnected outputs from separate analytical passes. The Evidence Intelligence Graph solves this without introducing opaque Graph Neural Networks (GNNs) or arbitrary weighted score averaging.

---

## 2. Core Scientific & Architectural Constraints

1. **Zero Fabrication**:
   - No fabricated nodes, edges, or MITRE ATT&CK techniques.
   - All relationships are derived strictly from observed network activity or deterministic correlation rules.
2. **Strict Scope Isolation**:
   - Nodes and edges are strictly partitioned into three scopes: `OBSERVED`, `FORECAST`, and `METADATA`.
   - Forecast nodes NEVER alter, overwrite, or feed backward into observed ground-truth nodes.
3. **No Arbitrary Score Averaging**:
   - Maliciousness is never determined by weighted arithmetic averages across modalities.
   - Contradictory evidence (e.g. periodic timing on a known benign protocol) is tracked explicitly via `CONTRADICTS` edges rather than being averaged away.
4. **Preservation of Canonical Model Contract**:
   - `MODEL_SCHEMA_45` remains the immutable feature vector contract for the NumPy LSTM world model.
   - Passive PCAP captures do NOT provide `mean_tcp_rtt`, and RTT is never fabricated.
5. **Deterministic Graph Identity**:
   - Node and edge IDs are strictly deterministic, derived from SHA-256 digests of their canonical identity tuples (e.g. `finding:<category>:<window>:<src>:<dst>`).
   - Re-running analysis on identical inputs produces bit-identical graph topology and traversals.

## 3. Graph Ontology: Node Types & Edge Types

### Node Types (`NodeType`)
| Node Type | Category | Description | Scope |
|---|---|---|---|
| `IP` | Network Entity | IPv4/IPv6 host address observed in traffic | `OBSERVED` |
| `PORT` | Network Entity | Layer 4 TCP/UDP destination service port | `OBSERVED` |
| `FLOW` | Network Entity | Unidirectional or bidirectional network flow | `OBSERVED` |
| `TCP_SESSION` | Network Entity | Stateful TCP conversation with Zeek-inspired lifecycle flags | `OBSERVED` |
| `COMMUNICATION_PAIR` | Network Entity | Host-to-host communication pair | `OBSERVED` |
| `WINDOW` | Temporal | Discrete 60-second temporal evaluation window | `OBSERVED` |
| `FINDING` | Analytical | Verified ML anomaly detection or heuristic security event | `OBSERVED` |
| `BEHAVIOR_SIGNAL` | Modality | RITA-inspired periodicity, regularity, or beaconing signal | `OBSERVED` |
| `PROTOCOL_SIGNAL` | Modality | Zeek-inspired session state anomaly (e.g. half-open SYN flood) | `OBSERVED` |
| `ANOMALY_SIGNAL` | Modality | Statistical flow anomaly or volume spike | `OBSERVED` |
| `FORECAST_SIGNAL` | Predictive | Future state forecast generated by NumPy world model (K=1..5) | `FORECAST` |
| `MITRE_TECHNIQUE` | Metadata | Empirical MITRE ATT&CK technique reference (e.g. T1046, T1498) | `METADATA` |
| `ATTACK_STATE` | Predictive | High-level attack progression state | `FORECAST` |

### Edge Types (`EdgeType`)
| Edge Type | Valid Source -> Target | Scope | Description |
|---|---|---|---|
| `COMMUNICATES_WITH` | `IP` -> `TCP_SESSION` / `PAIR` | `OBSERVED` | Host participates in network conversation |
| `USES_PORT` | `TCP_SESSION` / `PAIR` -> `PORT` | `OBSERVED` | Conversation targets specific service port |
| `PART_OF_SESSION` | `FLOW` -> `TCP_SESSION` | `OBSERVED` | Flow belongs to a stateful session |
| `OBSERVED_IN` | `FLOW` / `FINDING` -> `WINDOW` | `OBSERVED` | Event observed in 60s temporal window |
| `INDICATES` | `IP` -> `BEHAVIOR_SIGNAL` | `OBSERVED` | Host exhibits behavioral pattern |
| `SUPPORTS` | `PROTOCOL_SIGNAL` -> `FINDING` | `OBSERVED` | Protocol telemetry directly supports finding |
| `CORRELATES_WITH` | `BEHAVIOR_SIGNAL` -> `FINDING` | `OBSERVED` | Behavioral regularity correlates with finding |
| `MAPS_TO_TECHNIQUE` | `FINDING` -> `MITRE_TECHNIQUE` | `OBSERVED` | Finding matches empirical MITRE technique |
| `TEMPORALLY_PRECEDES`| `FINDING` -> `FORECAST_SIGNAL` | `FORECAST` | Past observed finding strictly precedes forecast |
| `FORECASTS` | `FORECAST_SIGNAL` -> `ATTACK_STATE` | `FORECAST` | Forecast projects future state continuation |
| `CONTRADICTS` | `BEHAVIOR_SIGNAL` -> `PROTOCOL_SIGNAL` | `OBSERVED` | Signals reach conflicting conclusions |

## 4. Formal Correlation Rules Registry (`RULES`)
All correlations are governed by the deterministic rule catalog `RULES` (R001 through R010):
- **R001 (`R001_SAME_ENTITY_COMMUNICATION`)**: Connects source `IP` to conversational `TCP_SESSION` or `COMMUNICATION_PAIR` via `COMMUNICATES_WITH`.
- **R002 (`R002_PORT_USAGE`)**: Connects session to destination `PORT` via `USES_PORT`.
- **R003 (`R003_SESSION_FLOW_MEMBERSHIP`)**: Maps individual reconstructed `FLOW`s to parent stateful `TCP_SESSION` via `PART_OF_SESSION`.
- **R004 (`R004_WINDOW_OBSERVATION`)**: Links temporal events to discrete 60s `WINDOW` via `OBSERVED_IN`.
- **R005 (`R005_PROTOCOL_SUPPORTS_FINDING`)**: Connects stateful session anomalies (e.g. SYN rejection bursts) to port scan findings via `SUPPORTS`.
- **R006 (`R006_BEHAVIOR_CORRELATES_FINDING`)**: Correlates RITA Bowley-skewness periodicity with findings on the same host via `CORRELATES_WITH`.
- **R007 (`R007_FINDING_MAPS_TECHNIQUE`)**: Maps verified findings to empirical MITRE ATT&CK techniques via `MAPS_TO_TECHNIQUE`.
- **R008 (`R008_TEMPORALLY_PRECEDES`)**: Links observed past findings to future forecast horizons via `TEMPORALLY_PRECEDES`.
- **R009 (`R009_FORECAST_MAPS_STATE`)**: Associates recursive multi-step forecasts with projected attack states via `FORECASTS`.
- **R010 (`R010_EVIDENCE_CONTRADICTION`)**: Explicitly tracks conflicting evidence between behavioral regularity and benign protocol semantics via `CONTRADICTS`.

---

## 5. Evidence Chains: Deterministic Attribution
The graph engine automatically compiles high-level `EvidenceChain` items by performing causal backward traversals:
1. **Observed Finding Chains**: Traced backward from each `FINDING` node to find all independent supporting signals (`SUPPORTS`, `CORRELATES_WITH`) and associated entities.
2. **Forecast Chains**: Traced backward from each `FORECAST_SIGNAL` (horizons $K=1 \dots 5$) through `TEMPORALLY_PRECEDES` edges to verify that forecasts are strictly grounded in observed historical evidence.
