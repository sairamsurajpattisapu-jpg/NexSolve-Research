# NexSolve Report Engine Specification

**Status**: PRODUCTION SPECIFICATION  
**Module**: `reporting/` (`report_engine.py`, `report_schema.py`, `report_sections.py`)  
**Endpoints**: `GET /jobs/{job_id}/report.json`, `GET /jobs/{job_id}/report.html`  
**SIH Problem Statement**: SIH26153 — AI based Network Attack Forecasting from Network Traffic Data  

---

## 1. Objective & Epistemic Framework

The NexSolve Report Engine compiles forensic evidence and temporal forecasting results into audit-grade, self-contained artifacts. In network security reporting, confusing observed alerts with model predictions or claiming uncalibrated raw scores as probabilistic truth damages operational credibility.

NexSolve structures every report section around five explicit **Epistemic Categories**:

| Category | Definition | Sections Governed |
| :--- | :--- | :--- |
| **`OBSERVED`** | Direct physical capture measurements, parsed packets, flow metrics, temporal continuity. | Capture Quality, Network Activity, Temporal Behavior, Provenance |
| **`INFERRED`** | Algorithmic deductions, heuristic threat scoring, observable evidence corroboration. | Executive Summary, Evidence Chain, Confidence / Uncertainty |
| **`FORECAST`** | Multi-horizon predictions of future attack activity ($T+1 \dots T+5$) generated by the world model. | Forecast Rollout, Attack Horizon |
| **`UNKNOWN`** | Out-of-distribution traffic, unsupported protocols, physical semantic contradictions. | Unknown Behavior Detection |
| **`ABSTAINED`** | Precondition violations or withheld outputs where telemetry cannot support inference. | Abstention Status, Suppressed Predictions |

---

## 2. Thirteen Formal Report Sections

1. **Executive Summary**: High-level status, overall observed threat level, top 5 observed heuristic findings, forecast duration, and epistemic policy disclaimer.
2. **Capture Quality**: Total vs. parsed packets, malformed count, truncation count, reordered packets, packet loss ratio, quality status (`HIGH`, `MODERATE`, `DEGRADED`).
3. **Network Activity Summary**: Macroscopic packet/byte throughput, flow counts, unique IPs and ports, protocol distribution (TCP/UDP/ICMP), TCP flag distributions.
4. **Temporal Behavior**: Window count (60s), timeline start/end UTC, rate trend, flow churn trend.
5. **Multi-Horizon Forecast Rollout**: Predicted attack probabilities $\hat{y}_h$, predicted stages, epistemic uncertainty, top contributing physical signals.
6. **Attack Horizon**: Onset window, lead time seconds, horizon duration, end timestamp, temporal consistency, decay observation.
7. **Evidence Chain**: Supporting vs. contradictory physical evidence items, relative change over 8-window baseline, evidence strength score ($0.0 \dots 1.0$), capture limitations.
8. **Confidence & Epistemic Uncertainty**: Raw score margin, calibration status (`UNSUPPORTED`), uncertainty level, mandatory calibration disclaimer.
9. **Unknown Behavior Detection**: Classification (`KNOWN_PATTERN`, `WEAK_PATTERN`, `UNKNOWN_BEHAVIOR`), physical contradiction rationale, feature coverage percentage, abstention recommendation.
10. **Abstention Status & Preconditions**: Availability gate status (`FORECAST_AVAILABLE`, `FORECAST_AVAILABLE_BUT_UNCALIBRATED`, `FORECAST_UNAVAILABLE`), missing requirements.
11. **Operational Limitations**: Capture pipeline flaws, model single-class domain caveats, heuristic boundaries.
12. **Provenance & Auditability**: SHA-256 capture hash, sanitized filename, byte size, model version, processing version (`nexsolve-v1.0.0-prod`). Zero local filesystem paths.
13. **Processing Metadata**: Job ID, generated timestamp, processing seconds, final stage.

## 3. Formats & Export Capabilities

### 3.1 JSON Format (`GET /jobs/{job_id}/report.json`)
* Media type: `application/json`
* Content-Disposition: `attachment; filename="nexsolve-report-{job_id}.json"`
* Validated against `reports/report_schema.json`.

### 3.2 HTML Format (`GET /jobs/{job_id}/report.html`)
* Media type: `text/html`
* **Zero External CDN Dependencies**: 100% inline CSS and standalone layout. Safe for air-gapped environments.
* **Printable CSS**: Formatted with `@media print` rules for clean PDF printing from any modern browser.
* **XSS Hardened**: All dynamic user-supplied strings are escaped via `html.escape()`.
